# Junshoku — differentiable grading node graph

This is a separate experimental implementation in the existing repository. It does not replace the LUT experiments on `main`.

## Architecture

A shared ImageNet VGG16 encoder extracts features from the source frame and the reference image.

- Global pooled deep VGG features are concatenated and passed through a shared MLP.
- Three independent parameter heads predict controls for serial operations: exposure/white balance, tonal contrast, and creative colour.
- A spatial fusion CNN combines source/reference feature maps. Three independent context-map heads predict one mask per node.
- Each node is applied sequentially, with a residual spatial blend:
  `output = input + context_map * (transformed_input - input)`.

The masks are independent sigmoid maps. They are not a softmax mixture because each mask controls a different sequential operation.

### Tensor conventions

Input source/reference/target: `[B,3,H,W]`, RGB float in [0,1].
Each node context map: `[B,1,map_size,map_size]`.
Parameter heads: exposure/WB 4 values, contrast 4 values, creative colour 5 values.
Output: `[B,3,H,W]`, clamped to [0,1].

The target image is the graded version of the source. The reference is the style/color reference, not the reconstruction target.

## 1. Environment (Windows PowerShell)

Use Python 3.10 or 3.11 for a conservative PyTorch/torchvision environment.

```powershell
git clone https://github.com/shayan-wasLazy/Junshoku.git
cd Junshoku
git switch cog-node-architecture
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Install PyTorch and torchvision using the command generated by the official selector for your machine: https://pytorch.org/get-started/locally/
Then install the remaining dependencies:

```powershell
pip install -r node_graph/requirements.txt
```

Verify CUDA:

```powershell
python -c "import torch; print(torch.__version__); print('CUDA:',torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal and activate again.

## 2. Dataset layout

The loader follows the existing repository's TST2K triplet convention:

```text
data/TST2K/
├── content_709/in1.png ...
├── paired_style/tar1.png ...
└── paired_gt/gt1.png ...
```

The loader creates a reproducible 90% train / 5% validation / 5% test split in split_manifest.csv on first run. It expects numeric sample folders containing exactly one image each named content, reference, and gt (extension may vary). Inspect the generated manifest before training. If samples are extracted from the same video, split by source video rather than randomly by frame to prevent leakage.

Update `data.root` in `node_graph/configs/default.yaml` to your actual TST2K path. For example, `F:/Junshoku/TST2K`.

## 3. Train

Run from the repository root:

```powershell
python -m node_graph.train --config node_graph/configs/default.yaml
```

Quick smoke test:

```powershell
python -m node_graph.train --config node_graph/configs/default.yaml --epochs 1 --batch-size 1
```

Checkpoints are saved under `checkpoints/node_graph/`.

## 4. Inference

Set `inference.input`, `inference.reference`, `inference.output`, and `inference.checkpoint` in YAML, or pass arguments:

```powershell
python -m node_graph.infer_image --source data/example/source.png --reference data/example/reference.png --output outputs/test.png --checkpoint checkpoints/node_graph/best.pt
```

## 5. Customize hyperparameters

Most experiment controls live in `node_graph/configs/default.yaml`:

- `data.image_size`, `batch_size`, `num_workers`, train/validation indices, and root.
- `model.pretrained`, `freeze_encoder`, `hidden_dim`, and `map_size`.
- Per-operation parameter ranges: `exposure_limit_ev`, `temperature_limit`, `tint_limit`, `contrast_limit`, `saturation_limit`, and `hue_limit`.
- `training.epochs`, `learning_rate`, `weight_decay`, `grad_clip_norm`, `amp`, and checkpoint directory.
- `loss.reconstruction` and `loss.map_smoothness`.

CLI overrides are available for `--data-root`, `--epochs`, `--batch-size`, and `--lr`.

For an 8 GB GPU, start with 256px, batch size 1–2, frozen VGG, and AMP. If you hit CUDA out-of-memory, lower `image_size` to 192 or 128 before changing the architecture.

## Important limitations / research TODOs

- This is a trainable research prototype, not a trained color-grading model. It needs the dataset and training before meaningful inference.
- Current node transforms are differentiable, simplified approximations of grading controls, not a full DaVinci Resolve color-science implementation.
- Current video inference/temporal stabilization is not implemented in this branch. Frame-wise processing can flicker; add temporal regularization or motion-compensated consistency before calling it video-ready.
- The masks are learned through reconstruction plus spatial smoothness. They do not have ground-truth semantic labels.
- The initial tiny TST2K split is for a smoke test only. Use a larger, properly split dataset for conclusions.
- Pretrained VGG16 weights are downloaded by torchvision on first use when `pretrained: true`.


## 6. Full TST2K evaluation report

The evaluation script follows the same reporting workflow as the earlier LUT experiments, adapted for the serial node-graph model. It evaluates the held-out `test` split and compares the model against an identity baseline (the unchanged source image).

Install the additional packages from the requirements file:

```powershell
pip install -r node_graph/requirements.txt
```

Evaluate the complete test split:

```powershell
python -m node_graph.evaluate --config node_graph/configs/default.yaml
```

Evaluate one sample only (only if its ID belongs to the test split):

```powershell
python -m node_graph.evaluate --config node_graph/configs/default.yaml --sample-id 0429
```

Evaluate the first 10 test samples:

```powershell
python -m node_graph.evaluate --config node_graph/configs/default.yaml --max-samples 10
```

Outputs are written to `Outputs/node_graph_evaluation/`:

- `metrics_per_image.csv`: per-sample model and identity L1, MSE, PSNR, SSIM, node parameters, and context-map means.
- `comparisons/`: four-panel source/reference/ground-truth/prediction images.
- `context_maps/`: visualizations and NumPy arrays for each of the three learned node masks.

The evaluation script also reports mean and standard deviation for each metric and counts how often the model beats the unchanged-source baseline on L1.

Note: the script requires the sample ID to be present in the existing held-out test manifest. It deliberately does not move samples between splits. If 0429 is not in the test split, use a test ID printed from the manifest instead.


## Context-map collapse fix (new training run required)

The fixed configuration bounds context gates to `[0.05, 0.95]`, initializes their logits at the neutral midpoint, reduces total-variation pressure, and adds a small spatial-variance floor. Training logs now report reconstruction, map smoothness, and map-variance terms separately. Evaluation CSVs include each map's mean, standard deviation, minimum, and maximum.

**Important:** this is a stabilization measure, not ground-truth supervision of where a grading operation belongs. Spatial variation alone does not prove semantic correctness; inspect the maps and image comparisons. A uniform map can be valid for a genuinely global adjustment.

The fixed config writes checkpoints to `checkpoints/node_graph_fixed/`. Train from scratch because the old checkpoint was trained with the previous map-head behavior:

```powershell
git pull origin cog-node-architecture
pip install -r node_graph/requirements.txt
python -m node_graph.train --config node_graph/configs/default.yaml --epochs 1 --batch-size 1
```

Evaluate the newly trained checkpoint:

```powershell
python -m node_graph.evaluate --config node_graph/configs/default.yaml --max-samples 10
```

Do not compare the new run with the old run unless you keep the same test samples, image resolution, and evaluation settings. The fixed run uses a separate checkpoint directory so the previous `checkpoints/node_graph/best.pt` is not overwritten.


## New training workflow: synthetic supervision, then TST2K fine-tuning

The current real-data-only objective cannot identify meaningful context masks from final-image reconstruction alone. The revised workflow first trains with synthetic examples where the generating node parameters and spatial masks are known, then initializes real TST2K fine-tuning from that checkpoint.

### Step A — supervised synthetic pretraining

```powershell
python -m node_graph.train_synthetic --config node_graph/configs/default.yaml --epochs 5 --batch-size 1
```

This creates `checkpoints/node_graph_synthetic/latest.pt`. Synthetic masks are smooth overlapping Gaussian regions; the target is generated by applying the known three node operations to a real TST2K content image. The generated target is also used as the synthetic reference cue so the model can infer the transformation during this controlled pretraining task.

### Step B — fine-tune on real TST2K triplets

```powershell
python -m node_graph.train --config node_graph/configs/default.yaml --epochs 20 --batch-size 1
```

The trainer initializes from `checkpoints/node_graph_synthetic/latest.pt` by default and writes real-data checkpoints to `checkpoints/node_graph_finetuned/`.

### Step C — evaluate

```powershell
python -m node_graph.evaluate --config node_graph/configs/default.yaml --max-samples 10
```

Evaluation reads `checkpoints/node_graph_finetuned/best.pt` through the config's `training.checkpoint_dir`.

### Interpretation caveat

Synthetic pretraining teaches the network to recover the synthetic mask/parameter generator. It does not prove that the masks correspond to semantically meaningful regions in real cinematography. The real-data fine-tuning objective can still change or collapse the masks; inspect map standard deviations and visualizations after both stages. Treat this as a controlled initialization experiment, not a guaranteed final fix.
